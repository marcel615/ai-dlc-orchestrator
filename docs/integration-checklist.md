# 통합 검증과 완료 판정

각 항목은 **통과·실패·보류·대상외** 중 하나로 판정하고 근거를 기록한다. 대상외는 이유가 필요하며, 미실행·자료 부족은 통과가 아니다.

## 기능·설정·공식 관계

- 선택 서비스와 설정 버전을 확인하고, Parent가 설정된 공통 관리 저장소에 있다.
- 공통 후보 제안은 `feature-discovery`의 최대 3개 Pending Draft 범위를 따르고, 정제는 `cross-project-backlog-refinement`에서 실제 Approved 후보만 처리했다. 기존 사용자 후보도 승인·식별자를 확인해 재사용하며 선행 Skill 실행 자체를 완료 요건으로 삼지 않았다.
- 자동 정제는 실제 Approved Draft에서 중복·미결정·우선순위·선행 관계를 검토해 최대 2개 선정했고 지정 후보를 우선했다. 보류·제외·기존 작업 재사용 근거를 보고했다.
- 제안·승인·정제·개발을 구분하고 다른 Skill이나 다음 개발 사이클을 자동 실행하지 않았다.
- 필요한 구현 작업만 해당 저장소에 존재한다. 한쪽만 필요한 이유와 미연결 역할의 미검증을 구분했다.
- Parent/Sub-issue 공식 관계를 실제 Issue ID로 양방향 조회했다. URL만 있는 상태를 연결 완료로 처리하지 않았다.
- 동일 Issue 생성·관계 중복 추가가 없고, 다른 Parent의 작업을 임의 재배치하지 않았다.
- Parent와 필요한 Sub-issue의 Project 등록·필드·상태 매핑을 확인했다.
- 권한·원본·공식 관계 조회 실패를 부재로 취급하지 않았다.

## 계약과 호환성

- 공식 요구사항·API·인증·ERD·UI의 설정 역할·기본 브랜치·경로를 실제 조회하고 원본 URL·commit SHA를 확인했다. 과거 `reference_commit`을 현재 버전으로 고정하거나 다른 저장소의 SHA를 적용하지 않았다.
- 구현 저장소에 남은 명세 사본을 공식 원본으로 취급하거나 공식 원본 조회 실패를 사본으로 대체하지 않았다.
- `templates/docs/`의 초기 작성 양식을 확정된 공식 명세로 취급하지 않았다. 실제 공식 명세는 설정된 원본에서 확인했다.
- Parent와 구현 작업은 공식 원본의 관련 URL·SHA를 참조하며 기능별 범위·완료 조건·결정을 관리하고 세부 명세를 불필요하게 복제하지 않았다.
- method/path·필수 입력·응답·오류·의미·권한과 쿠키·CSRF·CORS·토큰 수명·회전·실패 처리를 필요한 범위에서 확인했다.
- 원본 담당·소비자 검토·통합 조정·사용자 결정 책임이 명확하며 비호환 변경의 전환 순서를 확인했다.
- 원본과 구현 불일치는 해결하거나 사용자 판단 전까지 보류했다.
- ERD의 관계·제약과 구현 엔티티·마이그레이션의 영향을 필요한 범위에서 확인했고 중요한 DB 결정은 사용자에게 남겼다.
- UI 명세의 화면·경로·사용자 동작·공통 상태 처리와 Frontend 구현을 필요한 범위에서 대조했다. API·인증·데이터 구조는 각 공식 명세와 일치하며 미결정 UX를 임의 확정하지 않았다. 관련 UI 원본의 추가·변경은 분석 맥락에 포함해 재사용 여부를 판단했다.
- PR 탐색의 저장소별 기준 시점·조회 범위·실패 구간·이력과 분석 버전을 확인했다. 동일 맥락의 완료 분석만 재사용하고 새 head·base·공식 원본의 위치·요구사항·계약·소비자·결정 변경이나 보류 건은 재검토했다. 이전 분석이 현재 설정과 다른 명세 원본을 기준으로 수행되었다면 현재 공식 원본을 기준으로 재검토했다.

## 구현·통합 증거·재개

- 필요한 PR의 실제 Merge·Issue 종료 사유·대상 head의 CI·리뷰 결과를 확인했다. `not planned`는 구현 완료가 아니다.
- PR 본문의 성공 보고와 직접 조회한 실행 결과를 구분했다.
- Parent 완료 조건에 검증 환경·배포 필요 여부가 명확하고, 필요한 조합의 BE/FE commit·계약 SHA·검증 날짜·결과·증거가 있다.
- 인증은 영향 범위에 따라 로그인·재발급·로그아웃, CSRF·경합·탭 조정·401/403/503·응답 유실을 확인했다.
- 자식 완료율·자동 close·Project 자동화가 통합 검증 전 Parent를 완료 처리하지 않는지 확인했다.
- 부분 실패 재개에서 이미 생성된 Issue·공식 관계를 재사용하고 남은 단계만 수행했다.
- 남은 작업이 완료 조건을 막지 않는 이유와 제외 결정 출처가 명확하다.

## 보고

대상·시점·서비스·Issue/PR·계약 SHA, 단계별 실제 결과, 기존/제안 작업, 미검증·사용자 결정·재개 조건은 최종 응답이나 승인된 PR 본문에 보고한다.

별도 Markdown 검증 보고서는 만들지 않고 PR 중복 분석 방지에 필요한 최신 상태만 설정된 단일 JSON에 갱신한다.

분석·제안과 실제 생성·관계 연결·상태 변경·제품 테스트 결과를 구분하며 실행하지 않은 작업을 성공으로 보고하지 않는다.
