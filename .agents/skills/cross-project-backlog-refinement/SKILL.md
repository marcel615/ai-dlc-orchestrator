# 승인 후보 선정·정제와 작업 연결

루트의 `AGENTS.md`, `ai-dlc.yaml`, `docs/workflow.md`를 읽는다. 경로 기준은 저장소 루트다. 서비스·저장소 역할·Project·상태·라벨은 설정으로 해석하며 특정 서비스를 하드코딩하지 않는다. 정제 요청은 아래 후보 선정·Parent 전환·필요 Sub-issue 생성·공식 연결·초기 Project 반영을 포함한다. 정상 범위의 작업에 추가 실행 승인을 반복 요청하지 않는다. 사용자가 분석·계획만 요청하거나 범위를 제한하면 그 지시를 따른다.

`백로그 정제해` 요청에서 후보가 없으면 설정된 Project의 Draft 전체를 조회하고 실제 Approved 후보를 자동 탐색한다. 지정 후보가 있으면 지정 순서를 우선한다. 사용자·다른 경로의 후보도 승인 원본을 확인해 처리하며 feature-discovery 실행은 요구하지 않는다.

## 최대 2개 선정

workflow의 정제 후보 자동 선정 기준을 적용한다. 한 요청의 지정·자동 후보와 부분 성공 재개를 합쳐 최대 2개다. 특정 후보만 요청한 범위를 넘기지 않으며 유효 후보가 적으면 수를 채우지 않는다.

- 열린/닫힌 Issue·PR·Draft·전환 이력으로 중복을 확인한다. 이미 전환·구현된 기능은 새 Parent 대신 기존 작업을 보고하고 재사용한다.
- 목표 불명확·승인 확인 불가·우선순위 충돌·의존성 불명/순환은 보류한다. 세부 결정만 남은 후보는 질문·결정 라벨·Backlog로 정제할 수 있으나 Ready로 처리하지 않는다.
- Draft의 Project Priority를 설정으로 해석한다. 후보 간 확인된 선행 관계를 고려한 뒤 high→medium→low→미설정, 생성 시각 오래된 순→안정적인 후보 ID 순으로 검토한다. 실제 Issue의 라벨·Blocked by와 명시된 선행 조건도 확인한다.
- 선행 구현 미완료가 정제 자체를 막는 것은 아니다. 범위가 명확하면 의존 관계와 Backlog를 유지하며 구현 착수와 구분한다.
- 지정 후보부터 검토하고 남는 자리는 자동 선정한다. 지정 후보의 미승인·보류, 자동 후보의 선정·제외 근거와 조회 한계를 보고한다.

## 정제와 연결

UI가 관련된 후보는 공식 UI 명세의 화면·경로·사용자 동작·공통 상태 처리를 참조해 구현 범위와 완료 조건을 정리한다. API·인증·데이터 구조는 기존 공식 명세를 따르고 미결정 UX는 Parent의 결정 질문으로 남긴다.

선정 후보의 목적·범위·제외 범위·계약 참조·완료 조건을 정리하고 필요한 구현 역할에만 작업을 나눈다. 미연결 역할이 필요하면 그 부분을 보류하며 불필요하다고 간주하지 않는다. 각 구현안은 대상 저장소 템플릿과 독립 실행 요건을 따른다.

`requirements`의 공식 요구사항과 `contracts`의 API·인증·ERD·UI를 설정된 역할의 기본 브랜치·경로에서 조회하고 workflow에 따라 URL·SHA를 확인한다. Parent와 구현 작업은 관련 원본을 참조하고 기능별 범위·완료 조건·결정을 작성한다. 세부 명세를 복제하거나 Backend 사본을 공식 원본으로 대체하지 않는다. 원본 조회 실패·Parent나 구현과의 불일치는 해당 범위를 보류하고 중요한 요구사항·계약·인증·DB 결정은 사용자에게 남긴다.

Parent는 `backlog.parent_repository_role`이 지정한 저장소에, Sub-issue는 `backlog.implementation_repository_roles`에 정의된 역할 중 실제 필요한 구현 저장소에 둔다. 공식 GitHub Sub-issue 관계를 사용하며 URL만으로 대체하지 않는다. 같은 관계는 재추가하지 않고 다른 Parent로 자동 교체하지 않는다.

후보 승인·중복 재확인→Draft 전환→필요 Issue 생성/재사용→공식 연결→양방향 조회→Project 확인을 수행한다. 부분 성공은 기록하고 기존 Issue·관계를 재사용해 남은 단계만 재개한다.

신규 아이디어 발굴·Draft 등록·승인 변경은 하지 않는다. 선정·보류·중복 근거, 실제 Parent/구현 Issue와 미실행 본문안, 식별자·Link Key, 관계·우선순위·의존성·미결정·통합 검증 기준을 보고하고 종료한다. 다른 Skill이나 개발 사이클을 자동 시작하지 않는다.
